Estructura Base de una Historia de Usuario
📌 Descripción: Define el rol del usuario y sus necesidades específicas.
📌 Criterios de Aceptación: Determinan las funcionalidades y validaciones que debe cumplir la historia.
📌 Criterios de Finalización: Condiciones necesarias para considerar la historia como terminada.

Ejemplo:
📌 Descripción:
Como administrador del sistema, necesito gestionar categorías de productos (crear, actualizar, eliminar y consultar) para organizar eficientemente los productos dentro del sistema.

📌 Criterios de Aceptación:
✔ Permitir la creación, modificación, eliminación y visualización de categorías.
✔ Validaciones obligatorias, incluyendo restricciones de datos.

📌 Criterios de Finalización:
✔ Funcionalidad completamente implementada y probada.
✔ Código revisado y validado.
✔ Presentación al Product Owner.
✔ Documentación debidamente actualizada.
